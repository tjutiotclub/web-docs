# 交叉编译基础

开发主机与目标设备采用不同处理器架构时，需要使用面向目标平台的交叉编译工具链。本章解释工具链选择、目标架构和运行库匹配。

## 学习目标

- 区分本机编译与交叉编译。
- 理解 Build、Host 和 Target。
- 读懂交叉编译器的工具前缀。
- 使用工具确认二进制文件的目标架构。
- 理解 sysroot、ABI 和目标运行库的关系。

## 为什么需要交叉编译

开发板算力和存储通常有限，完整编译工作在性能更强的开发主机完成，生成的程序再复制到目标设备运行。

## Build、Host与Target

本节通过“在 x86_64 Ubuntu 上构建 ARM Linux 程序”的例子说明三个平台角色。

## 工具链前缀

```text
arm-linux-gnueabihf-gcc
aarch64-linux-gnu-gcc
```

解释架构、操作系统、ABI 与工具名称之间的关系，并介绍 `gcc`、`ld`、`ar`、`objcopy`、`strip` 等配套工具。

## 编译第一个目标程序

使用交叉编译器构建简单 C 程序，再通过以下命令检查产物：

```bash
file program
readelf -h program
```

## sysroot与运行库

sysroot 为编译器提供目标系统的头文件和库。目标程序能否运行还取决于 ABI、动态链接器和运行库版本是否匹配。

## 静态链接与动态链接

比较两种链接方式对文件大小、部署便利性、库更新和兼容性的影响。

## 部署到目标设备

通过 SCP 或其他传输方式复制程序，在目标设备添加执行权限并运行，再根据错误信息检查架构与动态库依赖。

## 常见错误

- `Exec format error`：程序架构与目标设备不匹配。
- `No such file or directory`：文件存在时，可能缺少动态链接器。
- `error while loading shared libraries`：目标系统缺少依赖库或库搜索路径不正确。
- 编译阶段找不到头文件或库：工具链或 sysroot 配置不完整。

## 本章实践

在开发主机上分别生成本机程序和 ARM 目标程序，比较 `file` 与 `readelf` 输出，并将目标程序部署到对应设备运行。

## 本章检查点

- 能根据目标设备选择正确工具链。
- 能判断一个 ELF 文件面向哪种架构。
- 能区分架构不匹配、动态链接器缺失和依赖库缺失。
